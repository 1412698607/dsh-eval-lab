## 实现与技术取舍

未发现需要修改生产代码的阻塞缺陷。排序载荷仅含规则版本、整数种子、用例条目 / 配置 / 重复编号；固定 UTF-8 JSON 与摘要字节排序不依赖进程 hash seed。sampleId 在排序之前分配，种子随完整清单和 order 进入原计划指纹。默认未声明种子不添加字段；0 与缺失、bool 分开。报告和续跑共用身份 / 顺序重建，先确认矩阵数量再展开，保持原预检边界。

新增续跑反例分别把保存种子 0 替换为 False，以及修改原 plan-input 清单中的种子；两者都在 UUID / 输出 / 领取前拒绝，源文件字节不因拒绝而变化。恢复原文件后仍可预检且计划摘要相同。测试首先断言原计划 eligibleForResume=true，避免用本来就不可续跑的输入证明拒绝。

分布测试让两个不同 entryId 指向同一个 caseId：一个条目有通过与失败，另一个有通过与缺证据。分别核对各条目的来源样本数合计等于原重复数、各来源共享同一分母、重复编号只出现一次，以及有效通过 / 失败 / 排除总数；源归档字节不变。已有测试继续覆盖 live / synthetic 声明分桶、坏路由、skipped、种子完整整数与缺字段展示。
