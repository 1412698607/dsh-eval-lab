# 修改记录 005 公开仓库过滤与私人资料隔离

日期：2026 年 10 月 11 日，Asia/Shanghai。类型：配置 / 文档。插件版本：`0.1.1`，行为未改变。相关 Git 提交：尚未提交。

## 问题与目标

仓库需要隔离可复现的技术资料、本地辅助文件、运行产物与凭据。原忽略规则已覆盖依赖、runs、部分缓存和环境文件，但没有排除本地辅助文档。增加过滤并调整导航，避免普通 git add 将本地资料加入版本管理，公开克隆也不依赖被忽略的文件。

## 文件修改

| 文件或范围 | 修改前 | 修改后 | 原因 |
| --- | --- | --- | --- |
| `.gitignore` | 基础依赖、运行目录和环境文件过滤 | 增加私人目录、旧私人文档位置、日志、覆盖率、编辑器与常见凭据文件过滤 | 减少非公开文件误提交 |
| `AGENTS.md` | 必须依赖公开目录中的个人文档 | 私人文件存在时维护，否则使用公开进度和方案；增加公开范围约定 | 公开克隆可独立使用 |
| README、CHANGELOG、progress | 导航链接指向私人资料 | 移除私人链接，保留公开技术文档入口 | 避免发布后出现失效链接 |

## 实现与技术取舍

私人目录使用根目录锚定规则 `/private-notes/`，旧的两个私人文档位置同样忽略，防止旧工具重新创建文件时被添加。环境文件保持忽略，仅保留 `.env.example` 例外；该例外要求使用占位值。保留源码、测试、脚本、架构、计划与技术修改记录，不以忽略整个 docs 的方式隐藏工程依据。

文档迁移前核对源和目标绝对路径都在项目内，目标不存在才执行单文件移动。移动后修正私人文档内的相对链接及接续提示。历史修改记录中的旧路径仍描述当时的改动，不覆盖历史验证；当前路径以开发约定及本记录为准。

只调整忽略与文档，不取消现有文件跟踪、不修改 Git 历史、不执行提交或推送。无关的既有 main.py 保持原状。

## 风险与后续

`.gitignore` 不是内容审查或保密机制：它不影响已跟踪文件，不清除历史，也不能防止强制添加。公开文档仍应审阅本机路径与内容；本批未进行完整凭据扫描或历史清理。私人资料不随克隆分发，需要时自行备份。公开仓库通过 progress、方案与修改记录保存接续必需的技术状态。
