## 实现与技术取舍

### 启动与错误清理

先读取并校验准备信息，拒绝已有 state / lifecycle / browser-url 等输出，以 wx 创建 terminal.log 后才启动专用子进程，避免旧日志冲突时已经创建资源。预检只处理启动前已知条件，不能替代启动后的错误处理。

启动成功后立即注册 onExit，再订阅输出；同步初始化、终端输出、观察文件和状态写入的可捕获错误保留首次原因，并唤醒监督循环。finally 先停计时器 / 观察循环及输入监听，再在必要时回收仍存活的专用进程。ConPTY 可能暂时返回 PID 0，清理阶段最多等待 10 秒取得有效自有 PID 并观察退出，绝不向 process.kill 传入 0；仅对当前 terminal 的正整数 PID 发 SIGKILL。只有实际 onExit 才填写 closed=true、原生退出码与信号；权限拒绝或期限内未观察退出时继续保留未关闭事实与清理错误。最终报告写入发生在回收之后，报告写入自身仍可能因磁盘错误失败，不能承诺失败报告一定保存成功。

runWeb 增加一个可选的终端创建函数参数，仅用于无模型回归；CLI 默认仍使用原来的 node-pty / ConPTY。确定性测试通过适配器启动实际、五秒有界 Node 子进程，并使用临时版本元信息满足版本检查，不安装 / 加载 Harness 或凭据。这验证监督与进程回收逻辑，不冒充原生 ConPTY；本轮另用实际安装的 node-pty 与十秒有界无模型 fixture 复验原生路径。

### 生命周期时间约束

非处理中断场景要求唯一 turn/end、SIGINT 和 observer/disposed，并满足 turn/end ≤ SIGINT ≤ disposed。正常场景额外要求 turn/end ≤ console-ctrl-c 操作时间 ≤ SIGINT。取消的操作时间是取消前检查点，继续沿用模型首流 ≤ 操作标记 ≤ 页面取消 ≤ turn/end，不把该标记误当作 Ctrl+C 时间。时间比较允许相等，不要求人为间隔。

录制器 / inspect、用例、run / JSONL / status / live 协议版本、原断言与 M2.3 控制器不变。取消 / 中断保持 unevaluable；旧取消样本的工作区未知不追溯补齐。

## 面试讨论点

资源预检与异常回收解决不同时间点的问题；要先注册退出观察，再处理可能失败的后续初始化或 I/O，不能用发出 kill 请求代替观察实际退出。时间戳逐项合法不代表跨来源因果顺序合法；取消检查点与退出操作属于不同阶段，不能共用相同的时间条件。
