## 问题与目标

Python urlsplit 与 JavaScript URL 对异常地址的解释不同。实测 https:///example.com/v1、百分号编码主机名及路径中的 U+0085 在 Python 被拒绝，却可通过 Node 直接入口；NUL 与空端口还被旧规则接受。需要在解析前统一地址语法，使准备 / 预检的有效输入范围一致。

## 实现与技术取舍

端点仅接受可打印 ASCII，原始 authority 为 ASCII 主机名及可选的非空数字端口；端口仍须 1～65535。保留禁止用户信息、查询串、片段和反斜杠。没有引入两种语言的共享运行时或额外依赖；用同一数据驱动的跨进程回归约束行为。

这是新可选字段的校验收紧，不变更插件 / 格式版本。050 已使用的百炼业务空间端点符合新规则，历史输入与原始证据不改写。

## 验证

新增一致性测试修复前失败，显示 Python 对 NUL / 空端口的遗漏；独立诊断另确认三个 Python / Node 分歧。修复后五项 modelProviders Python 回归 / 0.082 秒和六项 Node 定向回归通过。完整检查与 [052](2026-10-26-052-safe-batch-resume.md) 同轮运行，最终结果见该记录；本批无新模型任务，不沿用旧 CI 作为新改动验收。
