## 问题与目标

075 允许直接打开续跑结果，但详情仍需展开 JSON 才能查看实际尝试、跳过和用量汇总。实验续跑的 counts 是启动计划快照，若把 newSamples 当成实际执行数，会误读任务边界停止后的结果。本批分开展示身份、计划快照和两种保存汇总，不改变或补算结果。

## 实现与技术取舍

- 只对 batch_resume / experiment_resume 增加面板。保存的 outcome 独立显示，本轮通过不会覆盖历史失败或改写本结果结论；连续实验续跑的 sourceBatchId 表示最近来源批次，显示为“来源批次 ID”。
- 实验续跑 counts.original / reused / newSamples / blocked 明确标为“启动时”分类；批次结果没有 counts，不推导该计划。计划值不表示本轮完成数或当前剩余数。
- 直接并列 `newlyExecutedSummary` 与 `combinedSummary` 的计划、尝试、结束、跳过、错误、三类结论数量及三个比例分子 / 分母。实验的合并列覆盖全部原计划；批次的合并列仅覆盖当前来源批次计划，已包括其中复用和本轮新增，不包含更早祖先，不与本轮列相加。
- 用量表并列两种汇总的累计和观测 / 缺失样本。0 保持 0，null 或不存在的汇总保持缺失；实验版本 1 无 combinedSummary，右列仍显示缺失，不从其他文件或启动计划补值。
- 沿用原文本节点、表格和读取路径，不增加接口、依赖或结果格式。普通实验和版本 1 / 2 / 3 报告保留原布局；074 的本轮调度用量仍只读顶层 tokenUsage。
