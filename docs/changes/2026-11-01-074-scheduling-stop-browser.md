# 修改记录 074 调度停止结果浏览

日期：2026 年 11 月 1 日，Asia/Shanghai。类型：功能展示与回归测试。插件版本：`0.1.2`。起始提交：`3fbb8e6`。

## 问题与目标

任务数停止、已观测 token 停止及连续续跑已实现并完成各自验收，但浏览详情只能在折叠 JSON 中查看停止原因和本轮用量。增加直接可见的只读摘要，让使用者区分调度状态、实际停止原因、设置的阈值与缺失覆盖，避免把历史用量或阈值设置当作本轮触发事实。

## 实现与技术取舍

- 直接读取已保存的 `status / stopReason / stopAfter / stopAfterTokens / tokenUsage`，沿用原文件和读取接口，不改调度、报告或录制格式。配置报告不增加调度面板；其现有来源链接仍可打开各轮结果。
- 停止原因对七种当前代码值显示中文和原码：任务数阈值、token 阈值、用量不可用、失败策略、清理未确认、用户中断及 runner 错误。未知原因按原文作为文本显示。
- 仅顶层 `tokenUsage` 进入面板，不从 `summary / combinedSummary / reusedSummary` 补值，不把历史执行用量混入本轮。阈值和停止原因独立呈现；末项结束后即使超过阈值，也不从数值推断触发。
- 0 保持 0，显式 null 阈值显示“未设置”，不存在的字段和未采集用量显示“缺失”。stopReason 缺字段显示“缺失”；显式 null 且 completed 显示“未触发”，其他状态显示“无已保存停止原因”。保留旧文件可读性，未迁移或补写历史。
- 复用现有表格和文本节点，未增加依赖、接口或读取后写回。数值沿用六位有效数字显示，完整原值仍可查看 JSON。任务边界阈值不成为任务内 token / 费用硬限额。
