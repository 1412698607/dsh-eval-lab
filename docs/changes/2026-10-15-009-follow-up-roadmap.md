## 实现与技术取舍

顺序确定为：用例与离线断言 → 单用例真实运行 → Python 状态化工具环境及 JavaScript 实时桥接 → 顺序批次回归。先验证最小闭环和隔离，再做 M4 重复配置比较、统计报告与 M5 浏览 / 持续集成。

JavaScript 继续负责宿主、实时录制、工具注册和既有 inspect；Python 优先负责用例、断言、环境核心、调度及统计。计划区分执行状态、录制有效性与断言结论，保留 caseRunId 与 sessionId / runId 的关联要求。文件缺失等正常工具错误不自动归为运行错误。

未验证的 Web 手动取消、普通信号退出、desktop / SDK、自定义模型配置另列渠道待办；运行清单、单行限制和长期日志管理按实际使用问题分批评估。初版不引入并发，也不预设未验证的传输协议、命令或性能承诺。当前固定 fixture 检查与通用 M3 能力继续分开表述。
