# 修改记录 004 M2.1 输出与配置

日期：2026 年 10 月 11 日，Asia/Shanghai。类型：修复 / 配置 / 测试 / 文档。插件版本：`0.1.1`。相关 Git 提交：尚未提交；已有第一版提交为 `8c1b53a`。

## 问题与目标

第一版插件将启动信息写到 stdout，可能干扰 SDK JSON-RPC 或 headless JSON 输出；分发 patch 中的日志目录绑定开发机盘符。组件检查接受显式 node_modules 路径时没有核对版本，并通过遍历旧运行目录寻找日志，验证对象不够明确。

本批实现 M2.1：统一插件诊断到 stderr，使目录配置可移植，明确组件版本边界，以真实子进程检查输出。同时增加开发维护约定。录制状态、完整性与容量保护属于 M2.2，本批不实施。

## 实现与技术取舍

### 配置到文件的执行顺序

1. Harness 调用 apply；resolveConfig 先选显式 outputDir，没有值再选 DSH_EVAL_OUTPUT_DIR，最后用 homedir 拼出默认目录。
2. undefined 表示未配置；空字符串、相对路径、null 等选中值直接抛出指出来源的 TypeError，不会静默改变保存位置。
3. 将解析出的绝对目录交给独立记录器。记录器创建 UUID 目录及 run.json，插件在 stderr 输出实际运行目录。
4. 会话事件仍走原有序列化与 Promise 队列；检查点和关闭接口保持原状。仅插件版本字段更新，JSONL formatVersion 仍为 1。

把解析放在入口层，让独立记录器保持必须传入绝对目录的明确契约。环境与用户目录允许注入以便测试，不需要真正写入用户主目录。分发 patch 不再提供默认绝对覆盖；已有 profile 保存的显式路径仍优先，不自动改用户配置。

### 组件版本与运行身份

会话基线从 package.json 的可选 peer 读取，Cordis 固定 4.0.4。自动缓存查找跳过不匹配候选；显式路径版本不匹配立即报错，包含组件名、要求版本、实际版本和目录。校验发生在导入组件代码前。这里校验的是检查脚本使用的组件，并未额外在插件运行时重新加载宿主做版本检测。

每次检查创建唯一 check-id 子目录，只允许其中出现本次挂载产生的一个运行目录。读取 run.json 核对 runId、pluginVersion，再按本次新建 sessionId 定位 trace，避免历史文件导致误判。

原方案提到导入 FiberState；实际 Cordis 4.0.4 只声明 const enum，编译后的 JavaScript 无导出。改为本地命名常量 HOST_FIBER_ACTIVE，注释指明类型声明来源，并限定在通过固定版本校验后使用。方案已同步这一实施修正。

### 真实进程输出与宿主错误行为

check:output 通过 execFile 直接启动 Node，无 shell；分别捕获 stdout、stderr，设置超时与输出上限。子进程真实挂载 Cordis、SessionStore 和插件，不打印成功摘要。正常场景提交 6 条人工事件并比较日志；错误场景先在目标 JSONL 路径创建目录，触发实际 appendFile 错误，验证 session/flush 拒绝。两个场景都要求 stdout 为空，stderr 包含启动诊断；错误场景额外要求写入失败诊断。

第一次沙箱内运行因 spawn EPERM 未启动子进程。获准在沙箱外运行后，正常场景通过，错误场景暴露检查脚本的错误假设：它期待 fiber.dispose 拒绝。对照实际实现确认 Cordis 4.0.4 的卸载捕获清理错误，因此改为使用 session/flush 验证失败传播，dispose 仅负责资源清理，修正后两个场景通过。

这不是将错误用例改为忽略：真实写入错误仍必须使 flush 拒绝并产生 stderr 诊断，stdout 的全量断言仍保留。该发现说明 M2.2 的封存状态不能由宿主卸载结果替代。

## 风险与后续

- 默认日志位置从开发机固定路径变为用户目录；演示和检查仍显式写入项目 runs。已有 profile 中保存的显式配置不自动迁移。
- stdout 的组件边界已验证，完整 SDK、headless、ACP 或桌面生命周期未验证，不宣称这些入口已全面兼容。
- 尚无状态文件、摘要、容量上限或离线 inspect。错误保存在内存，强制退出及断电没有可靠性保证。
- 当前仅验证固定组件版本，不自动升级或推断其他版本兼容性。
- M2.2 先实现录制片段状态与检查；M2.3 再进行实际 profile 与真实模型任务联调。
