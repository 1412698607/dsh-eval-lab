# 修改记录 077 执行批次检查点关联

日期：2026 年 11 月 1 日，Asia/Shanghai。类型：功能。插件版本：`0.1.2`。尚未提交；起始提交为 `3fbb8e6`，保留 074–076 工作区改动。

## 问题与目标

实验和批次续跑在执行前已保存 batchBinding，但 batchResultPath 通常到最终收尾才填入。外层进行中结果无法通过关联区进入已经写入的批次检查点，只能等待最终结果或另行寻找目录。本批直接暴露已有保存关联，不增加执行或重新评测行为。

## 实现与技术取舍

- 仅在顶层 batchResultPath 不存在、null 或空字符串时使用字典型 batchBinding.resultPath，沿用原 add / reference 的文本范围预检、真实路径复核和文件存在检查。
- 外部、UNC、私有或缺失目标保持不可用；不读取来源目录猜路径，不启动 / 续跑任何任务。显式批次路径存在时维持原链接，即使它失效也不借绑定隐式替换，避免掩盖保存元数据问题。
- 标签明确为保存关联，不验证 batchId 或其他身份。用户可手动刷新重新读取子批次已保存的检查点；外层文件仍可能停留在 running 或旧汇总，不承诺多文件在线一致快照。
- 不增加 API、文件格式、授权范围或新文件类型，普通终态关联保持原行为。
