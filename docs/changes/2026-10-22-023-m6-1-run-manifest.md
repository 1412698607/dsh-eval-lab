## 问题与目标

旧 inspect 只检查目录中发现的会话文件。一个会话的 JSONL 和 status 同时被删除后，其他片段仍可以 complete；全部会话被删除只会显示没有片段，无法证明应有成员丢失。

本批让新运行保存应有会话集合，检查成员缺失、清单开放和终态失败，同时保留旧格式的片段检查结果并明确其运行级覆盖未知。只实施已同意的 M6.1，后续三批仍是计划。

## 实现与技术取舍

### 清单与异步顺序

直接扩展 run.json，复用既有临时文件加 rename 的 JSON 替换函数，不再维护第二份清单文件。版本 2 中保留原元信息，增加 runManifestFormatVersion=1、state、sessions。每个条目固定 sessionId、traceFile、statusFile，文件名必须由会话哈希推导。

初始空清单为 recording。首次会话登记在内存加入集合时捕获快照，进入独立运行队列；该会话的状态 / JSONL 等待登记保存成功。多个会话的登记严格串行，避免旧快照覆盖新集合。会话内仍使用原写入队列与字节统计，record / flush 的排队与检查点语义不变。

close 先停止接收，等待全部会话队列，然后保存 sealed 或 failed 清单。单会话失败不阻止健康会话封存，但整体不能 complete。登记或最终清单保存失败时 flush / close 报 AggregateError，运行错误只上报一次，回调异常不能替换原错误；清单写入失效后停止接受新事件。失败状态本身可能无法保存，磁盘仍可为 recording、缺失或临时文件，不补造成功。

### 格式与兼容

选择运行元信息 formatVersion=2，避免旧 inspect 忽略新增清单后把新格式误当旧片段成功；JSONL 行和会话状态均保持 1。清单结构另有 runManifestFormatVersion=1。插件保留当前开发版本 `0.1.2`，以文件版本识别能力，不为改动公共用例而连带变更全部配置引用。

升级 inspect 接受旧版本 1，原有完整片段仍可 complete / 0，但新增 runManifest.outcome=unverified 和覆盖未知原因，不改写历史。旧版整对文件消失仍不能检测，不扩大旧证据保证。版本 2 删掉清单字段，或只把元信息降到 1 却保留清单，都不按旧格式放行。

### 检查与下游

已知清单严格校验身份、哈希名、重复和状态；对照目录，sealed 清单任一成员文件缺失或出现未登记会话均 invalid / 1。recording 清单即使已有状态全部 sealed 仍 unverified / 2，确定损坏优先 invalid。未知未来清单版本保留不确定；空 sealed 清单不改变“没有片段”的整体 unverified。

报告新增 runManifest 格式 / 状态 / 预期数量 / outcome / reasons，缺失会话也在 sessions 保留登记身份。Python 复用 Node 的整体 outcome，invalid / unverified 不运行断言，因此无需重写评测器或改变已有 evidence / evaluation 版本。浏览仅放宽录制元信息的版本读取，不自动复验、不扩展路径权限。

清单每新增会话保存完整成员快照，增加元信息 I/O；本批没有资源或性能测量。日志仍只是新增事件，清单不提供签名、在线一致快照、fsync、断电恢复或会话重放；观察前和未持久化登记窗口的内容不能由清单补造。

## 风险与后续

运行清单只能检测已持久化且保留下来的清单所登记成员。清单、版本、日志和摘要被同时修改，或整个运行目录被删除，不在当前检测保证内；SHA-256 不是签名。旧 inspect 不支持元信息版本 2，必须配套升级，不能绕过版本检查来读取。

下一批 M6.2 计划单条事件上限与资源基线；M6.3 真实评测集和 M6.4 Web 生命周期验收尚未实施，共余三批。日志轮转、desktop / SDK、并发与续跑仍是按需候选。
