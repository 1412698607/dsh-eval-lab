## 问题与目标

用户要求实际验证 GitHub 云端 CI。查询到 `db6d572` 对应 push 运行 `39623812949`，作业 `119303889060` 失败。环境准备、31 文件 JS 语法和 44 项 Node 测试通过；133 项 Python 中两项路径检查失败，后续 compileall 和合成 demo 被跳过，不能记为云端通过。

云端临时目录使用 `RUNNER~1` 短路径写法，而 `Path.resolve()` 返回完整路径。浏览服务只保留真实根目录作为预检前缀，导致配置路径写法下的合法 runtime 关联被误判为越界。另一个报告迁移测试把已经解析的证据路径与未解析的目标目录作字面比较，错误地判失败。

本批兼容显式配置目录的别名写法，保留根外引用的解析前预检，并实际复验云端结果。

## 实现与技术取舍

启动时仅登记用户显式配置路径的绝对文本写法及其解析后位置，并建立前缀到真实根的对应关系。引用先匹配这些已登记前缀、检查禁用目录，再解析并核对真实根。未配置的外部路径不会为寻找别名而先做 `resolve()`；原 UNC / 私人目录 / 越界回归保留。没有加入磁盘全局别名发现或取消范围预检。

新回归使用 Windows 真实目录 junction（其他平台为符号目录），把它显式配置为 runs 根，验证该写法中的绝对 runtime 关联与真实路径均能打开。未配置外部路径继续在 `resolve()` 前被拦截。报告只修正测试中的路径规范化，不改变报告算法、冻结输入核对或历史文件。

## 面试讨论点

可以解释“本机和 CI 都是 Windows”仍可能因账户目录短路径、运行时补丁版本及路径规范化不同而暴露问题；复现应覆盖真实目录别名，而不是删除失败断言或放宽根目录边界。
