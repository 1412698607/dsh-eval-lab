日期：2026 年 10 月 21 日，Asia/Shanghai。类型：修复 / 测试 / 文档。插件版本：`0.1.2`。相关 Git 提交：本批尚未提交；M5 主体已核实为 `36b4e1b`。记录 020 中的“尚未提交”为当时状态。本批开始时工作区干净，分支为 `20261011/feat/results-browser-ci`。

## 问题与目标

M5 审查发现四个问题：关联路径在范围判断前调用 `resolve()`，未配置的 UNC 位置也可能触发本机路径查询；深层 JSON 的 `RecursionError` 会中断目录或轨迹 HTTP 请求；混合包含已知与缺失来源的结果无法被“缺失”筛选找到；批次的结构化异常直接显示为 `[object Object]`。

本批先用回归复现，再修复浏览路径、解析隔离和页面显示。浏览继续只读取保存内容，不改变任务分类、统计口径或原始证据。

## 实现与技术取舍

关联路径先用不跟随符号链接的 `abspath` 规范化文本，判断是否属于显式根目录及允许的目录分量；不满足就返回缺失 / 超范围标记。通过后才调用 `resolve()`，再次检查真实位置和禁用目录。文件读取仍核对所属根、扩展名和存在性，轨迹目录通过相同预检后才枚举。原合法根内相对关联、符号目录 / junction 逃逸检查和循环排除回归保持通过。

浏览器局部解析包装复用原严格 JSON 解析器，将解析递归溢出转为 `ValueError`，并用迭代检查限制对象 / 数组容器最多 128 层。显式上限让浏览响应有足够的序列化余量，不调整全局递归限制或原评测器。超深文档在目录中单独显示错误，直接打开返回错误 JSON；超深 JSONL 行保留原行号、错误与最多 2048 字节原文预览，后续正常行继续显示。128 层仅是浏览限制，不是对原证据有效性的判定。

目录响应的 `sources` 对样本缺失、空或非字符串来源保留临时 `unknown`；有明确单次来源时继续使用其原声明。页面的“缺失”筛选同时接受此标记和无来源集合的旧响应，因此同一结果可出现在多个来源筛选中。原文件、来源声明、分母及任务结论不改写；`browserFormatVersion: 1` 和持久化格式均不变。

前端不引入模块拆分或运行依赖。新增 Node 回归以最小 DOM 替身运行原 `app.js`，触发实际筛选和打开详情事件，检查可见文字；它验证交互逻辑，不替代真实浏览器排版或视觉验收。

## 风险与后续

超过 128 层的 JSON 现在只在浏览入口报错或显示行预览，原文件仍保留，可用原离线工具显式处理。路径检查不提供并发修改时的一致快照或本机文件权限隔离。页面仍展示保存结论，不能据此确认当前证据完好。

四项审查问题已由针对性回归覆盖；后续验收仍是提交后核对托管 CI。真实浏览器布局、本机恶意修改、远程多用户访问及其他原有限制没有新增验证。
