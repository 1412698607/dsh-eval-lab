## 实现与技术取舍

沿用原严格加载和全局关联检查。读取已校验清单 / 保存结果 / 批次后，先用 cases × configurations × repetitions 计算预期数，验证 samples 与 entries 都为列表且长度一致，再创建位置生成器核对固定顺序。Python 整数直接计算，不以逐项枚举计数；不改变重复编号、身份匹配、跳过 / 失败分母、计划指纹或报告字段。

两项新增测试以 10^100 重复数及非法容器构造实际保存输入，用受控枚举哨兵保证修复前可安全失败，避免为了复现耗尽内存；随后再通过真实 Python CLI 验证巨大重复数的新 / 旧格式副本快速返回输入错误 2，没有 inspect 或新输出目录。

Node 入口保留同一进程，只选择正式 test 目录的 *.test.js。不依赖 Git 忽略、不删除副本、不引入测试框架或额外启动器。现有 85 项中的真实子进程仍按原方式运行，环境权限不足不能算通过。

## 风险与后续

此修复避免报告对数量不一致输入先展开矩阵，不提供输入文件字节 / 总内存硬上限。有效报告仍读取全部保存样本并做完整复验。计划 / 录制摘要仍不是签名。

## 面试讨论点

输入校验不仅要检查最终字段，还要在昂贵操作之前执行：先直接算数量再枚举，才能让拒绝本身保持有界。Git 忽略、测试发现、公开提交范围是三个不同边界；本机 170 个通过不等于正式 85 项通过，更不能代替最新提交的云端验收。
