## M6.2 当前交付与边界

maxEventBytes 默认 1 MiB，按包含包装字段与换行的整行 UTF-8 字节计量，在 Buffer 分配与反解析之前拒绝；maxPendingBytes 保留 16 MiB 默认值，二者独立。超限不截断原始证据，触发会话 failed、整体 inspect invalid，Python 不运行任务断言。新 run.json 保存有效配置，格式版本不变，历史日志无需迁移。

M6.2 审查修复补齐任务入口：用例顶层可选 recorder 声明两限制，完整冻结并经单用例 / 批次 / 实验传入隔离 profile；不混入 configRef，不改默认策略。真实配置合并及无模型组件验证通过，详见 [记录 026](../changes/2026-10-23-026-m6-2-recorder-config-propagation.md)。

新增 `npm.cmd run measure:recorder`，8 类场景各 3 个新进程，实际写文件并在边界和 10 ms 间隔采样 heap / external / arrayBuffers / RSS，同时统计清单写入。24 样本的输入、结果与局限见 [录制资源边界](../recorder-resources.md) 和 [记录 025](../changes/2026-10-22-025-m6-2-event-resource-limits.md)。单条限制仍在同步序列化之后；采样显示超限输入仍消耗临时堆、分批登记仍重写完整清单。没有总内存硬限额、性能提升或长期负载结论。

这一批不自动包含日志轮转。轮转需要另外定义分段顺序、摘要、清单和 inspect 兼容；应在实际日志规模确有需要后单独安排。

## 沿用的边界

- JavaScript 负责 Harness / Cordis、录制、inspect 与宿主生命周期；Python 负责用例、环境核心、执行计划、断言与报告。
- 正常确定性 CI 不调用模型。真实模型先使用单独选择的显式命令；未来若增加模型 CI，应另设手动触发、凭据与预算，不默认每次 push / PR 运行。
- 当前 timeoutSeconds 不是总退出硬上限或费用硬限额；token / 步骤 / 费用预算尚未实现，后续设计只能声明实际能强制执行的限制。
- 日志仍是新增事件片段，不承诺完整会话备份、确定性重放、fsync 或断电恢复。清单及 SHA-256 都不是签名。
- desktop / SDK、并发、崩溃续跑、跨实验合并和统计推断是候选扩展，不因列在此处就视为已计划固定工期或已实现。
