## M6.1 当前交付

新 run.json 版本 2 内含 runManifestFormatVersion=1、recording / sealed / failed 和会话清单；JSONL 包装及会话状态仍为版本 1。首次会话文件写入等待登记成功，运行清单使用独立串行队列，close 最后保存终态。后续审查修复将待执行登记合并为共享批次，在开始时生成快照，并为适当的 rename 错误增加有限重试，详见 [记录 024](../changes/2026-10-22-024-m6-1-registration-reliability.md)；这两项修复属于 M6.1，不表示 M6.2 已实施。旧 inspect 拒绝版本 2，升级 inspect 可读旧版本并明确其会话覆盖未知。

详细协议、判定矩阵和兼容边界见 [运行会话清单](../run-manifest.md)，实际命令与验证见 [记录 023](../changes/2026-10-22-023-m6-1-run-manifest.md)。插件保持 `0.1.2`；本批未提交、推送或触发新的托管 CI，不继承 M5 云端通过作为本批结果。

## M6.2 开始时先确定的内容

先读取现有队列容量和新清单快照开销，再设计单条字节限制与错误状态。现有 maxPendingBytes 只覆盖排队文本，不是序列化临时对象或总内存硬限额；单条限制也不能未经测量就宣称解决全部内存问题。测试使用可控输入、实际文件与进程，性能结论必须注明规模、平台和测量口径。

这一批不自动包含日志轮转。轮转需要另外定义分段顺序、摘要、清单和 inspect 兼容；应在实际日志规模确有需要后单独安排。

## 沿用的边界

- JavaScript 负责 Harness / Cordis、录制、inspect 与宿主生命周期；Python 负责用例、环境核心、执行计划、断言与报告。
- 正常确定性 CI 不调用模型。真实模型先使用单独选择的显式命令；未来若增加模型 CI，应另设手动触发、凭据与预算，不默认每次 push / PR 运行。
- 当前 timeoutSeconds 不是总退出硬上限或费用硬限额；token / 步骤 / 费用预算尚未实现，后续设计只能声明实际能强制执行的限制。
- 日志仍是新增事件片段，不承诺完整会话备份、确定性重放、fsync 或断电恢复。清单及 SHA-256 都不是签名。
- desktop / SDK、并发、崩溃续跑、跨实验合并和统计推断是候选扩展，不因列在此处就视为已计划固定工期或已实现。
