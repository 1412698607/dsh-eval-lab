更新：2026 年 10 月 18 日，Asia/Shanghai。状态：M3.1 离线断言和 M3.2 单用例真实运行已完成；M3.3 状态化桥接及同日复查两项修复已完成当前范围；M3.4 顺序批次已完成当前范围。插件当前版本 `0.1.2`；实际命令和格式见 [评测格式](../evaluation-format.md) 与 [单用例运行](../single-case-runner.md)。

## 起点与阶段目标

M2.3 已验证独立 Web / headless profile 的真实任务与生命周期，固定检查器保持原范围。M3.1 新增通用离线断言；M3.2 已能自动准备独立文件环境并驱动一条真实 headless 用例。事实与范围以 [开发进度](../progress.md)、[修改记录 010](../changes/2026-10-16-010-m3-1-offline-evaluation.md) 和 [修改记录 011](../changes/2026-10-17-011-m3-2-single-case-runner.md) 为准。

M3 的目标是让一组有明确输入、初始环境和预期结果的用例可以重复执行，得到可追溯的任务结论。先完成命令行与结构化结果，再开展配置比较和界面。当前真实驱动支持单用例及顺序批次，合成演示仍不属于真实模型任务或批次模型验收。

### M3.1：已完成的离线范围

第一版用例包含版本、caseId、任务输入、初始文件声明、必需断言、超时预算声明与配置引用。配置包含 provider / model / profile / 插件版本，不内嵌凭据。包位于 `dsh_eval/`，离线命令为 `python -m dsh_eval --case ... --evidence ...`，公开样例在 `fixtures/evaluation/`，保留 main.py；M3.1 本身不执行环境，M3.2 已补真实文件准备和墙钟预算，M3.3 已补状态化工具。

当前断言为最终文本、工具参数与返回内容 / isError、callId 关联、结果在答案之前、结束原因；未增加 JSON 字段断言。工具名由用例声明，不硬编码 read_file。未知事件保留，不猜测含义；缺必要证据报告 insufficient_evidence，不能默认通过。单任务内序号缺口和结构错误保守处理。

Node inspect 仍负责录制检查，Python 不复制其摘要和封存校验实现。已使用公开合成轨迹验证正反例，标明不是模型证据；本批未复验旧模型输出，公开仓库不依赖被忽略的日志。

### M3.2：已完成的单用例范围

正常读取任务已从用例到结构化结果 passed；启动错误、未知路由、两秒超时、流后取消分别验证为无法评测，录制有效性独立记录，并检查专用子进程已退出。任务预算包括启动和执行，准备 / 清理另计，不支持 token / 步骤上限。现有 demo 仍仅写合成证据。验证及限制见 [单用例运行](../single-case-runner.md)。

## 结果分类与关联

M3.1 已实现三个维度，M3.2 已采集并验证受控真实运行事实，避免把取消、模型回答错误和录制损坏混为一种失败。下表为约束，具体字段和版本 1 / 2 枚举见 [评测格式](../evaluation-format.md)。

| 维度 | 需要表达的事实 | 对任务结论的影响 |
| --- | --- | --- |
| 执行状态 | 正常结束、用户取消、预算超时、启动 / 路由 / 工具桥接等运行错误 | 非正常完成不能直接当作普通任务断言失败 |
| 录制状态 | Node inspect 的 complete / invalid / unverified 及原因 | invalid / unverified 不进入普通任务通过或失败统计 |
| 断言结果 | 必需断言全部通过、明确不满足、未执行或证据不足 | 仅在正常完成且录制有效时判断任务 passed / failed；其余保留无法评测及原因 |

工具正常返回 isError 是任务证据，不自动归为运行错误；例如预期的文件缺失和暂时故障可由模型处理。桥接无法通信、协议损坏等基础设施错误需要单独报告。预算只能声明实际可执行的限制，尚未支持的 token 或步骤限制不能当作已强制执行。

每次执行生成 caseRunId，与 caseId、批次标识、实际 sessionId、录制 runId 和输出路径建立显式关联。caseRunId 表示一次用例执行，不能用插件启动 runId 代替，也不假设两者永久一一对应。初版每个用例使用新主会话和独立 workspace；恢复会话、fork 和子 Agent 不纳入首版验收。

输出需要保留用例版本、初始输入、实际配置、预算、执行状态、录制检查、逐条断言和错误原因。调用次数、token、耗时、费用只有实际采集且口径明确时才填写，缺失保持缺失。结构化结果与原始日志分别保存，原始会话继续放在被忽略的 runs。

## 语言与进程边界

| 部分 | 计划职责 |
| --- | --- |
| JavaScript | Harness / Cordis 接入、工具注册、实时录制、宿主生命周期和既有 inspect；复用 M2.3 已验证的启动与清理路径 |
| Python | 用例校验、初始环境、任务断言、状态化环境核心、单用例与批次调度、后续统计与报告 |
| 离线连接 | 版本化用例 / 结果与 JSONL，Python 调用现有 Node inspect 的明确进程接口 |
| 实时工具连接 | 必须单独设计请求 / 响应协议，不能靠离线 JSONL 返回工具结果；实现前先核对当前宿主的注册和取消接口 |

实时桥接至少需要明确协议版本、请求标识、caseRunId / 会话关联、操作与参数、成功或错误响应，以及取消 / 超时后的状态处理。以当前环境状态和实际参数决定返回，不按全局调用序号机械回放历史答案。重试、重复请求和中途退出如何处理，已在 M3.3 落实为 JSONL / IPC，详见状态化工具协议。

Python 调度复用已有宿主适配和检查，不另写一个 Agent 循环。正常退出时先让 Agent 停止产生事件，再结束桥接与宿主并检查日志；异常或强停要保留实际退出事实，不补造完成事件。首次实现先验证单进程与顺序运行的资源清理。

## 首批候选用例

| 用例 | 初始状态与任务 | 必需证据 |
| --- | --- | --- |
| README 路径过时 | README 引用已不存在的说明文件，环境中存在可发现的新路径；任务要求找到并返回其中的 projectName | 实际旧路径失败、发现并读取有效文件、最终字段正确；输入和结果按 callId 关联，不能直接把答案写进工具模拟 |
| 工具失败后恢复 | 目标文件存在，但该路径的读取在受控暂时故障状态下失败；任务允许重试或采取合理替代路径 | 真实工具错误后继续处理，环境按该路径 / 操作的状态转移，后来取得有效结果并正确回答；每次用例执行重置故障状态 |

先在 Python 环境中验证状态转移，再接入实际宿主工具，最后运行真实模型。环境单测、宿主桥接和真实模型任务分别记录；合成轨迹不能替代最后一步。用例可约束必要行为，不强制模型执行与目标无关的固定调用顺序。
