## 打开与停止

在项目根目录运行，需要 Python 3.12 或更高版本，无需安装前端依赖：

```powershell
python -m dsh_eval --browse
```

终端输出一行 JSON，其中 `url` 是带本次访问令牌的本机地址。完整打开该地址；默认自动选择空闲端口。页面不自动打开浏览器，终端按 Ctrl+C 停止服务。关闭页面不会停止服务。

默认用例库是 `fixtures/evaluation`，结果目录是 `runs`。可以指定其他目录或端口：

```powershell
python -m dsh_eval --browse --cases-root fixtures/evaluation --runs-root runs --port 8765
```

`--runs-root` 在浏览模式中仅表示读取位置，不会创建目录。独立放置的报告、实验及录制目录，需要在指定结果根目录内才能互相打开；不存在或超出范围的关联显示“缺失或超出浏览目录”，不搜索其他磁盘位置。旧报告中的绝对路径迁移后可能失效，浏览器不会修补历史文件。

配置目录使用 Windows 短路径或目录别名时，服务同时保留显式路径写法和解析后真实根，关联文件可使用这两种位置表示；其他未配置前缀仍需通过范围预检。

浏览不能与 `--run`、`--evidence`、`--output`、`--reports-root` 或宿主控制选项混用。启动成功时服务持续运行，Ctrl+C 正常返回 0；非法端口或绑定失败输出错误 JSON 并返回 2。

## 从列表到证据

页面分为实验、实验续跑、配置报告、批次、批次续跑、逐次结果和用例库。用例库收录 `*.case.json`；结果列表收录 `experiment-result.json`、`experiment-resume-result.json`、`report.json`、`batch-result.json`、`resume-result.json`、`evaluation.json`，冻结输入及报告中的复验结果通过关联文件打开，避免把每份快照都当成一个新用例。续跑标题优先使用保存的名称或 resumeId，不从来源文件推测名称。支持名称 / 标识 / 路径搜索、任务结论筛选及来源声明筛选；“刷新文件”重新读取目录。

来源筛选保留样本中的缺失声明，因此同一实验 / 报告可同时出现在真实运行、合成和缺失筛选中。缺失来源仅在浏览响应中标为 `unknown`，不修改原 `source`；失败样本的结构化异常显示类型与消息。

续跑目录的来源来自本结果的保存声明：优先读取合并摘要的 `sourceCounts`；没有该摘要时，合并本轮新增摘要与历史复用行的来源，计数只接受正整数。实验启动计划的 pending 行不表示终态来源；本轮摘要或历史声明缺失时保留 unknown。目录不沿来源链接读入其他文件，不生成新的复验或模型来源认证。

- 实验与报告显示原计划样本、全尝试通过比例、可评测通过比例及可评测覆盖，比例同时显示分子 / 分母，零分母仍为缺失。
- 批次、实验、批次续跑和实验续跑详情显示保存的 `status / stopReason / stopAfter / stopAfterTokens / tokenUsage`。停止原因与阈值分别呈现：设置阈值不表示触发，全部任务结束时即使用量超过阈值也可为 completed / stopReason=null。token 阈值触发、用量不可用、失败策略及执行错误分别解释并保留原码；未知原因按原文显示。
- 调度面板的用量只读顶层 `tokenUsage`，只含本轮新增尝试，不读取历史 / 合并汇总来补值。0 保留为 0；阈值为 null 显示“未设置”，旧文件缺字段或未采集的用量显示“缺失”。停止原因缺字段显示“缺失”；显式 null 且 completed 显示“未触发”，其他状态显示“无已保存停止原因”。这些保存值不能作为任务内 token / 费用硬限额或新的复验结论。
- 续跑详情的“续跑身份与启动计划”显示本结果任务结论和来源身份；实验续跑的 counts 仅表示启动预检时的原计划、历史复用、本轮计划及阻断数，不表示本轮实际完成或结束后剩余数。批次续跑没有该字段，不补算实验计划。
- “续跑保存结果汇总”和“续跑保存用量”分别显示 `newlyExecutedSummary` 与 `combinedSummary` 中的计划 / 尝试 / 结束 / 跳过 / 错误、任务结论数量、比例分子分母及观测 / 缺失用量。实验续跑的合并列覆盖全部原计划；批次续跑的合并列仅覆盖来源批次计划，包含其中复用项，不代表更早祖先或整个原实验。合并列均已包含本轮，不能与本轮列相加。实验续跑版本 1 没有合并摘要，进行中结果也可能未保存摘要，相应列保持缺失；不会从计划、原实验或关联子结果填补。原任务结论独立保留，不以本轮通过覆盖历史失败。
- 样本行显示请求配置、实际 provider / model、配置匹配、来源声明，以及执行 / 录制 / 断言三维结果。点击样本打开保存的逐项评测，再进入用例快照、证据清单、执行事实、录制状态及事件轨迹。
- 配置报告显示保存的 `verification`、`saved.outcome` 与 `changedFields`，并展示同来源共同配对数量、排除、逐指标观测 / 缺失配对、右减左差值及范围。`verified` 显示为“复验已处理”，不等于任务通过。完整保存值可在折叠 JSON 中核对。
- 版本 2 报告额外显示原实验 / 续跑身份、两个批次及保存的计划 / 续跑关联复核状态；样本可直接跳转各自来源批次。历史复用和本次新增分别显示计划 / 尝试 / 跳过、来源、通过分母和指标累计 / 缺失覆盖；全部原计划汇总明确包含历史复用，分组保留两类样本数。实验 / 批次续跑结果既可直接从各自目录打开，也保留报告关联入口。版本 1 保留原布局，未知版本拒绝。
- 指标保留缺失，不用零替代。页面数值保留六位有效数字，原 JSON 不变；时间按 Asia/Shanghai 显示。
- JSONL 每页默认 50 行，可前后翻页，保留原行号和原事件。无法解析的行显示错误及预览；超过 64 KiB 的行只显示最多 2048 字节预览，不将预览当作完整记录或断言证据。

进行中实验或批次续跑可能尚未保存 `batchResultPath`。若本文件已有 `batchBinding.resultPath`，关联区显示“执行批次检查点（保存关联）”，可打开范围内已存在的批次文件；随后可手动刷新读取其新检查点。绑定目标缺失 / 越界时显示不可用，不启动任务、不搜索其他根。终态已有显式批次路径时沿用原链接，不重复或借绑定替换错误的显式路径。绑定是保存的关联，不验证 batchId，也不保证多个文件在同一时刻一致。

浏览只显示保存时的内容，不调用 `evaluate`、Node inspect、runner 或模型，不改变历史结果。`complete`、`passed` 和配置匹配均是文件中保存的结论，可能已过时；`live` / `synthetic` 是来源声明，不是签名。需要重新检查日志和断言时，使用现有离线入口：

```powershell
python -m dsh_eval --report 'runs/experiments/<experimentId>/experiment-result.json'
```

这个命令会单独生成新报告；页面刷新后可以查看。单用例复验仍使用 [评测格式](evaluation-format.md) 的 `--case ... --evidence ...` 入口。

## 断言诊断与证据定位

[079](changes/2026-11-01-079-assertion-diagnostics.md) 为逐次评测结果增加“断言诊断 · 失败优先”。每条卡片显示保存的 ID、类型、结论与原因；failed 项先显示，其余保留原顺序。原断言 JSON 和完整结果仍可查看。

- 期望值只取当前 evaluation 内嵌的 `case.assertions`，按 ID 与类型唯一匹配；不会读取现行用例文件替代历史快照。缺失、类型不符或重复匹配时显示无法匹配。
- `final_text` 展示 `equals` 与保存的 `actual`，高亮去掉共同前后缀后剩余的不同区间。使用 Unicode 码点切分，原文本仍完整显示；这是简易差异区间，不是最小编辑脚本。转义视图区分空字符串、空格和换行，不去除 Markdown 或修改结论。评测器保存的实际答案已经去除首尾空白，原始答案仍须查看事件。
- `turn_end` 对照保存的结束原因；`tool_result` 展示工具、参数、结果谓词和可选 after。现有工具断言结果未保存实际工具正文，卡片明确显示缺失，使用证据按钮查看原始内容，不从保存结论反推实际值。不执行、证据不足与失败继续保持不同结论。
- 按保存的 `callSeq / resultSeq / afterResultSeq / answerSeq / endSeq` 提供跳转；工具失败的多个证据候选保留，重复按钮去重。没有有效非负安全整数序号时不生成跳转。
- 目标文件来自 evaluation 的 `association.runDir` 与 `sha256(sessionId).jsonl`，必须通过原目录范围检查；缺少运行 / 会话身份或目标文件时显示不可用。定位同时匹配 JSONL 包装中的 runId、sessionId 和 event.seq，不把 seq 当作物理行号，也不选目录中的任意第一份轨迹。
- 点击后显示目标周围的一页事件，高亮并聚焦目标行，分别列出物理行号和事件序号；可返回诊断页。目标缺失、重复、读取时目标行已变或超过预览范围时显示错误并保留原诊断页，不悄悄跳到第一页。

定位搜索最多读取 8 MiB，沿用单行 64 KiB 与 JSON 深度限制；超限、无法解析的行不能作为定位匹配。超过搜索上限时仍可手动分页查看原始轨迹。只做保存关联的定位，不提供完整性复验、来源认证、实时一致快照或自动修复；应使用稳定归档。

## 读取边界与限制

Python 标准库服务仅绑定 `127.0.0.1`，仅提供静态页面和读取 API。API 要求本次启动生成的随机令牌，令牌在 URL fragment 中传给页面，随后用请求头访问 API；拒绝不匹配的 Host / Origin，不开放跨域读取，不缓存响应。浏览器在当前标签页会话中保存令牌以支持刷新，重新启动服务须使用新地址。这不是面向远程或多用户的登录系统。

文件必须落在显式的两个根目录内；关联路径先规范化文本并检查范围和禁用目录，再解析真实路径并复核。根外绝对路径、相对越界路径和未配置的 UNC 位置不会先被解析。每次读取仍拒绝目录穿越、隐藏路径、NTFS 备用流及 home / workspace / private-notes / secrets 等目录。扫描不跟随符号目录或 Windows junction，避免绕入私人目录或循环。任意脚本、普通文本输出和凭据文件没有下载入口，原始 JSON / 事件内容通过文本节点显示，不执行其中的 HTML。

目录最多列出 2000 项，超过后明确提示截断；单份 JSON / Markdown 最大 8 MiB，JSON 对象 / 数组容器最多 128 层；轨迹 API 每页最多 200 行、offset 最大 1000000。超深 JSON 文档在列表中单独报错，直接打开返回错误；超深轨迹行显示原行号、错误及预览，后续正常行继续显示，不将浏览限制当作证据无效结论。页面不是实时一致快照，不提供编辑、运行按钮、自动复验、目录监控、完整大文件下载、流式全文搜索或跨实验合并。应浏览停止写入后的稳定文件。访问令牌不能代替本机文件权限或保护已被同一用户修改的证据。审查修复与回归见 [记录 021](changes/2026-10-21-021-m5-review-fixes.md)。

## 无模型持续集成

[确定性工作流](../.github/workflows/deterministic.yml) 在 push、pull_request 和手动触发时，使用 Windows runner、Node.js 24 和 Python 3.12，依次运行：

```powershell
npm.cmd run check
npm.cmd test
npm.cmd run test:python
python -m compileall -q dsh_eval test
npm.cmd run demo:eval
```

不安装 Harness 或项目依赖，不配置模型密钥，不执行 `--run`，不上传原始运行目录。测试中的确定性适配器会启动真实 Node / Python 子进程，使用原录制器、inspect 与状态化工具，但不调用模型。`smoke:host`、`check:output` 和真实工具注册 smoke 需要本机的固定 Harness 安装，不属于这个干净环境工作流。

真实模型验收继续使用明确的 `--case / --batch / --experiment ... --run` 命令，预算来自用例 `timeoutSeconds`，调用前需单独选择任务与配置；本批没有新增模型自动工作流，也没有 token / 费用硬限额。工作流权限仅 `contents: read`，checkout 不保留凭据，整项检查上限 15 分钟。

Action 用法核对自官方 [checkout](https://github.com/actions/checkout)、[setup-node](https://github.com/actions/setup-node)、[setup-python](https://github.com/actions/setup-python) 说明。2026 年 10 月 21 日实际验收已通过：`e47de36` 的运行 `39625366038` 为 `success`，31 文件语法、44 Node、134 Python、compileall 和 demo 均成功。之前 `db6d572` 因 Windows 路径写法差异失败的记录保留。原实现与历史验证见 [记录 020](changes/2026-10-21-020-m5-results-browser-ci.md)，失败、修复与云端证据见 [记录 022](changes/2026-10-21-022-cloud-ci-path-aliases.md)。
